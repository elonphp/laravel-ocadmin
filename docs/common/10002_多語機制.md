# 多語機制

本系統的多語分為三個層面，各自獨立運作，共用同一份設定檔。

- **介面多語** — `lang/` 語系檔 + `__()`，用於固定 UI 文字（按鈕、標題、提示訊息）
- **網址多語** — 網址第一段 `/zh-hant/`、`/en/` + `SetLocale` middleware，每次 request 自動切換語系；可設定預設語系不帶語系段
- **內容多語** — `xxx_translations` 翻譯表 + `HasTranslation` trait，用於後台管理的動態資料（分類名稱、詞彙名稱等）

---

## 語系檔架構策略

### 設計原則

本系統參考 OpenCart 4.x，其前台（catalog）與後台（admin）語系檔完全分離、互不依賴。
採用相同思路，以**第一性原理**與**最小阻力**為指導：

- **第一性原理**（Elon Musk）：問題本質是「讓每個 Portal 能獨立運作、獨立翻譯」，而不是「如何讓前後台共用語系檔」。
- **最小阻力方向**（Peter Lynch）：不統一，就不用花力氣決定邊界。前後台各自維護，重複不是問題。

(語言檔放哪裡，在引用第一性原理、最小阻力方向之前，已來回移動多次。若要再改變路徑，請慎重。)

### 為什麼不共用

曾多次嘗試將前後台語系檔合併共用，但每次都因邊界模糊而反覆調整：

- 同一個 key 前後台語意可能不同（後台「新增」vs 前台「加入」）
- 前台不需要 `button_export`、`text_confirm_batch_delete`
- 後台不需要 `text_add_to_cart`、`text_checkout`
- 硬要共用反而要不斷做「這個 key 前台要不要」的判斷

### 最小阻力分析

| 面向 | 說明 |
|------|------|
| **前後台分離** | 各自維護，拿掉一個不影響另一個，符合 OpenCart 參考架構 |
| **不用 Portal 目錄** | 放專案根目錄 `lang/admin/`，後台換架構（換 view layer）語言檔仍可沿用 |
| **重複詞彙無妨** | `button_save` 兩邊都有沒關係，複製一次就好，之後各自演化 |
| **語意分歧自由** | 不用花時間判斷哪些共用、哪些分開，各 Portal 自行決定用詞 |
| **模組化** | 每個 Portal 是獨立單元，語系檔跟著走 |

### 呼叫方式

#### 後台（Blade + TranslationLibrary）

每個 Controller 透過 `setLangFiles()` 宣告所需語言檔，
由基底類別 `OcadminController` 在 middleware 中呼叫 `TranslationLibrary` 載入至 `$this->lang`。

```php
// OcadminController 基底類別（自動載入 admin/default）
protected function getLang(string|array $groups): void
{
    $this->lang = app(TranslationLibrary::class)->load($groups);
}

// 子類別覆寫，指定模組語言檔
class OptionController extends OcadminController
{
    protected function setLangFiles(): array
    {
        return ['admin/catalog/option'];  // 自動合併 admin/default
    }
}
```

Controller 中使用 `$this->lang->key`，View 中使用 `$lang->key`：

```php
// Controller
$this->lang->heading_title       // 選項管理

// Blade
{{ $lang->button_save }}          // 儲存（來自 admin/default）
{{ $lang->heading_title }}        // 選項管理（來自 admin/catalog/option）
```

> 衍生專案若採其它前台架構，多語載入模式抽到 research：
> - **Livewire**（server-side reactive）：[`docs/research/livewire_多語機制.md`](../research/livewire_多語機制.md)
> - **前後端分離**（Inertia / Vue / React SPA）：[`docs/research/前後端分離的多語機制.md`](../research/前後端分離的多語機制.md)

#### 全域（Model 層、跨 Portal）

```php
__('global/enums.status_active')       // 啟用
```

### 不使用 namespace

語系檔放在專案根目錄 `lang/`，不透過 `loadTranslationsFrom()` 註冊 namespace。
Laravel 預設的 `__()` 直接以目錄路徑作為 key 前綴，無需 `ocadmin::` 等前綴。
好處：任何 Portal、任何層級都能直接存取，不受 ServiceProvider 註冊順序影響。

## 統一設定檔

`config/localization.php`

```php
return [
    'supported_locales'   => ['zh_Hant', 'en'],
    'default_locale'      => 'zh_Hant',
    'hide_default_locale' => false,   // 見 §二
    'detect_preferred'    => false,   // 見 §二
    'url_mapping'         => [
        'zh-hant' => 'zh_Hant',   // URL 格式 → 內部格式
        'en'      => 'en',
    ],
    'locale_names'        => [
        'zh_Hant' => '繁體中文',
        'en'      => 'English',
    ],
    'legacy_paths'        => [],      // 見 §二
    'bcp47_aliases'       => [ /* 瀏覽器語言對照，見設定檔註解 */ ],
];
```

統一存取方式（不直接呼叫 `config()`）：

```php
use App\Helpers\Classes\LocaleHelper;

LocaleHelper::getSupportedLocales();   // ['zh_Hant', 'en']
LocaleHelper::getLocaleNames();        // ['zh_Hant' => '繁體中文', 'en' => 'English']
LocaleHelper::getDefaultLocale();      // 'zh_Hant'
LocaleHelper::getCurrentLocale();      // 當前語系（內部格式）
LocaleHelper::toUrlFormat('zh_Hant');  // 'zh-hant'
LocaleHelper::toInternalFormat('zh-hant'); // 'zh_Hant'
```

## 一、介面多語（Laravel 語系檔）

用途：按鈕文字、欄位標題、提示訊息等**固定的 UI 文字**。

### 目錄結構

詳見上方「語系檔架構策略」章節。

### 使用方式

Blade 中：

```blade
{{ __('admin/default.button_save') }}        {{-- 儲存 / Save --}}
{{ __('admin/default.text_confirm_delete') }} {{-- 確定要刪除嗎？ --}}
```

PHP 中：

```php
__('admin/default.column_name')  // 名稱 / Name
```

### 新增語系檔

以新增後台「員工模組」語系為例：

```
lang/zh_Hant/admin/hrm/employee.php
lang/en/admin/hrm/employee.php
```

```php
// lang/zh_Hant/admin/hrm/employee.php
return [
    'heading_title' => '員工管理',
    'column_employee_id' => '員工編號',
];
```

使用：`__('admin/hrm/employee.heading_title')`

### 語言 Key 命名慣例

| 前綴 | 用途 | 範例 |
|------|------|------|
| `heading_` | 頁面標題 | `heading_title` |
| `text_` | 一般文字、訊息 | `text_list`, `text_success_add` |
| `column_` | 欄位標籤（列表、表單、篩選共用） | `column_name`, `column_display_name` |
| `placeholder_` | 輸入提示 | `placeholder_name` |
| `help_` | 欄位說明 | `help_name` |
| `error_` | 錯誤訊息 | `error_has_roles` |
| `button_` | 按鈕文字 | `button_save`（通常放 common） |
| `tab_` | Tab 標籤 | `tab_trans`（通常放 common） |

> **不使用 `entry_` 前綴。** 因為列表欄位標題與表單欄位標籤大部分相同，統一使用 `column_` 避免重複定義。篩選欄位標籤也直接複用 `column_*`。

### 語系如何切換

`SetLocale` middleware 在每次 request 根據 URL 呼叫 `App::setLocale()`，之後所有 `__()` 自動使用對應語系目錄的檔案。

## 二、網址多語（URL Locale）

用途：以網址第一段（語系段）區分語系，讓同一頁面可透過不同網址切換語言。

### 1. 支援的三種形態（只改 `config/localization.php`）

| 形態 | `supported_locales` | `hide_default_locale` | 網址 |
|---|---|---|---|
| 多語系、一律帶語系段（範本預設） | `['zh_Hant', 'en']` | `false` | `/zh-hant/admin/x`、`/en/admin/x` |
| 多語系、預設語系不帶語系段 | `['zh_Hant', 'en']` | `true` | `/admin/x`（中文）、`/en/admin/x` |
| 單一語系、不帶語系段 | `['zh_Hant']` | `true` | `/admin/x`；網址裡完全沒有語系段 |

另一個開關 `detect_preferred` 決定「網址沒帶語系段時用哪個語系」，只在 `hide_default_locale=false` 時有意義：

| `detect_preferred` | 沒帶語系段時 |
|---|---|
| `false` | 一律預設語系 |
| `true` | 依序取第一個有效的：帳號的預設語言（`users.locale`；資料表沒有這個欄位就跳過）→ session（這次瀏覽最後看過的語系，`SetLocale` 寫入）→ 瀏覽器語言（`Accept-Language`，經 `bcp47_aliases` 對照）→ 預設語系 |

> `hide_default_locale=true` 時沒帶語系段＝預設語系，**不偵測**。否則同一個網址會因人而異顯示不同語言，網址就失去意義。
>
> 帳號排在 session 前面：已登入的人以帳號設定為準，不因為剛點過一頁英文，之後不帶語系段的網址就全變英文。沒有帳號設定（或沒登入）時，才沿用這次瀏覽最後看過的語系。

### 2. 行為規則

| 網址 | 帶語系段（`hide=false`） | 預設語系不帶語系段（`hide=true`） |
|---|---|---|
| `/{預設語系}/存在的路徑` | 正常顯示 | **301** → 去掉語系段的網址 |
| `/存在的路徑` | **302** → 補上語系段（預設或偵測到的語系） | 直接顯示預設語系（內部補上，不重導） |
| `/{其他支援的語系}/存在的路徑` | 正常顯示 | 正常顯示 |
| `/{語系}/{舊路徑}/...` | 依 `legacy_paths` 改寫，改寫後存在才重導 | 同左 |
| 無效 / 已停用的語系、不存在的路徑 | **404** | **404** |
| 路徑存在、HTTP 方法不對 | **405** | **405** |

兩條原則：

1. **只重導到確實有路由接得住的網址，否則直接 404**（`LocaleHelper::isRoutable()`）。
2. **語系段只接受有效語系**：路由群組用 `where` 限定，無效的語系進不了語系路由。

> **為什麼要有這兩條**：少了它們，系統分不出「沒帶語系段」與「帶了無效的語系段」——兩者第一段都不是有效語系。
> 於是 `/ja/admin/x` 被當成沒帶語系段，補成 `/zh-hant/ja/admin/x` 送出去，到了那裡才 404。
> 停用某個語系（從 `supported_locales` 拿掉）之後，舊書籤就會全部變成這樣。
> 先驗證目的地，就不必區分這兩種情況：那種網址直接 404，不猜、不補。

### 3. 元件

| 元件 | 職責 |
|---|---|
| `config/localization.php` | 各專案唯一要改的地方 |
| `App\Helpers\Classes\LocaleHelper` | 共用邏輯：語系清單、`routePattern()`、`resolvePreferred()`、`isRoutable()`、`switchUrl()` |
| `App\Http\Middleware\SetLocale` | 掛在 `{locale}` 群組上：依語系段設定 `App::setLocale()`、`URL::defaults()`、記進 session，並從路由參數移除 `locale`（Controller 收不到）。`hide` 時使用者自己帶了預設語系段的 GET → 301 到不帶的網址 |
| `App\Http\Middleware\HideDefaultLocale` | 只在 `hide_default_locale=true` 時掛成全域 middleware（比對路由之前）：沒帶語系段的網址在內部補上預設語系段 |
| `App\Http\Controllers\LocaleFallbackController` | fallback 路由（所有路由都沒對上時）：補語系段、舊路徑改寫，目的地存在才重導，否則 404 |
| `App\Providers\LocaleServiceProvider` | 組裝：`URL::defaults` 預設語系、把 `SetLocale` 排在登入檢查之前、`hide` 時掛 `URL::formatPathUsing()` 與上面的 middleware、註冊 fallback 路由 |

除了 `config/localization.php`，以上檔案在所有衍生專案**應保持同一份**。

### 4. 路由定義

```php
// app/Portals/Ocadmin/routes/ocadmin.php
Route::group([
    'prefix'     => '{locale}/admin',
    'as'         => 'lang.ocadmin.',
    'middleware' => 'setLocale',
    'where'      => ['locale' => \App\Helpers\Classes\LocaleHelper::routePattern()],   // ← 必加
], function () {
    // ...
});
```

- **每個 `{locale}` 群組都必須加 `where`**。不加的話任何第一段都會進群組——連 `POST /dev/login` 都可能被 `{locale}/login` 搶走。
- **不要再自己寫補語系段的轉址路由**（`/admin/{any?}`、`{any}` catch-all）。那是 `LocaleFallbackController` 的工作；它掛在 fallback 路由上，永遠排在所有路由之後，不必靠路由檔的載入順序。

### 5. `hide_default_locale` 怎麼做到「路由檔不必改」

路由照舊定義在 `{locale}` 群組底下，route name 也不變，差別只在網址的外觀：

```
進來：/admin/x          ── HideDefaultLocale ──▶ 內部當成 /zh-hant/admin/x 比對路由（瀏覽器網址不變）
出去：route('lang.ocadmin.x') = /zh-hant/admin/x ── URL::formatPathUsing ──▶ /admin/x
```

- 判斷順序是**根層級路由優先**：`/foo` 本身就有路由（刻意定義在根層級的 `/`、`/auth/*`、`/logout`、`/api/*`）就照原路徑；沒有，才補上預設語系段當語系路由。
- ⚠ **兩邊同一個網址都有路由時，語系路由那一條會被遮住。** 最常見的是 `/`：根層級定義了首頁，語系群組的 `/{locale}/` 不帶語系段時也是 `/`。
  語系群組裡的那一條要換路徑（例如後台首頁用 `/{locale}/dashboard`）；根層級也不要再定義「轉址到 `/zh-hant/...`」的路由——轉過去會被去掉語系段轉回來，形成迴圈。
- 帶了預設語系段的網址（舊書籤、寫死的連結）由 `SetLocale` 301 到不帶的網址，不在 `HideDefaultLocale` 做：
  後者在 session 啟動之前，那裡重導會吃掉 flash（驗證錯誤、舊輸入）。`SetLocale` 重導前會 `reflash()`，fallback 的重導也是。
  `SetLocale` 被排在登入檢查之前，所以未登入時也是先 301 成乾淨網址，再導去登入頁。
- `request()->path()` 在內部仍是 `zh-hant/admin/x`（與帶語系段時一致）；`url()->current()`、`route()` 產生的則是 `/admin/x`。
  **拿 `request()->url()`、`fullUrl()` 去跟 `route()` 比對的程式要改用 `url()->current()`。**
- 完整網址字串（`https://...`）不經過 `formatPathUsing`。session 記的「上一頁」、登入後回到原頁的 intended URL 都是內部網址（帶語系段），`back()`、`intended()` 會多一次 301 才落地，結果仍正確，flash 也保得住。
- 寫死在 Blade / JS 裡的 `/zh-hant/...` 也會被 301 導正，但應改成 `route()` / `url()`。

### 6. 語系切換選單

連結網址一律由後端產生，不要在前端替換網址第一段（`hide_default_locale` 時預設語系根本沒有語系段可換）：

```blade
@foreach(\App\Helpers\Classes\LocaleHelper::getLocaleNames() as $locale => $name)
    <a href="{{ \App\Helpers\Classes\LocaleHelper::switchUrl($locale) }}">{{ $name }}</a>
@endforeach
```

`getLocaleNames()` 只回傳支援中的語系；只有一種時選單應整個隱藏。

### 7. Middleware 註冊

```php
// bootstrap/app.php
$middleware->alias([
    'setLocale' => \App\Http\Middleware\SetLocale::class,
]);

// bootstrap/providers.php
App\Providers\LocaleServiceProvider::class,
```

### 為什麼用 Middleware 而不是在路由檔直接呼叫 Helper

路由檔直接呼叫 `LocaleHelper::setLocale()` 作為 prefix，在 `php artisan route:cache` 時 prefix 會被固定成單一語系，導致其他語系 404。Middleware 搭配 `{locale}` 路由參數則不受 route cache 影響。

## 三、內容多語（Translation Tables）

用途：由使用者在後台管理的**動態資料**，如分類名稱、詞彙名稱、商品名稱等。

### 資料表結構

每個需要多語的主表，建立對應的 `xxx_translations` 翻譯表：

```
taxonomies                    taxonomy_translations
┌────┬──────┬───────┐        ┌────┬─────────────┬────────┬──────┐
│ id │ code │ ...   │        │ id │ taxonomy_id │ locale │ name │
├────┼──────┼───────┤        ├────┼─────────────┼────────┼──────┤
│  1 │ skill│       │───────→│  1 │           1 │zh_Hant │ 技能 │
│    │      │       │        │  2 │           1 │ en     │Skills│
└────┴──────┴───────┘        └────┴─────────────┴────────┴──────┘
```

翻譯表固定欄位：`id`、`{主表}_id`（外鍵）、`locale`，其餘為可翻譯欄位。

### Model 設定

**主表 Model**（使用 `HasTranslation` trait）：

```php
use App\Traits\HasTranslation;

class Taxonomy extends Model
{
    use HasTranslation;

    protected $fillable = ['code', 'description', 'sort_order', 'is_active'];

    // 宣告哪些欄位是可翻譯的（這些欄位不在主表，在翻譯表）
    public array $translatedAttributes = ['name'];
}
```

**翻譯 Model**（命名慣例：主表名 + `Translation`）：

```php
class TaxonomyTranslation extends Model
{
    public $timestamps = false;
    protected $fillable = ['taxonomy_id', 'locale', 'name'];
}
```

### 存取翻譯

```php
// 自動根據當前語系回傳（透過 getAttribute 覆寫）
$taxonomy->name;                    // "技能"（當 App locale = zh_Hant）

// 指定語系
$taxonomy->translate('en')->name;   // "Skills"

// 帶 fallback
$taxonomy->translateOrDefault('ja')->name;  // 找不到 ja，回傳 fallback 語系

// 取得所有翻譯（陣列）
$taxonomy->getTranslationsArray();
// ['zh_Hant' => ['name' => '技能'], 'en' => ['name' => 'Skills']]
```

### 儲存翻譯

```php
$taxonomy->saveTranslations([
    'zh_Hant' => ['name' => '技能'],
    'en'      => ['name' => 'Skills'],
]);
```

### 查詢 Scope

```php
// 依翻譯欄位模糊查詢（當前語系）
Taxonomy::whereTranslationLike('name', '%技%')->get();

// 篩選有指定語系翻譯的記錄
```

### 新增可翻譯 Model 的步驟

1. **建立翻譯表 migration**：`xxx_translations`（id, xxx_id, locale, 可翻譯欄位）
2. **建立翻譯 Model**：`XxxTranslation`（`$timestamps = false`）
3. **主表 Model 加入 trait**：`use HasTranslation`，宣告 `$translatedAttributes`
4. **主表不放可翻譯欄位**：`name` 等欄位只在翻譯表

---

## 三者的關係

| 層面 | 資料來源 | 切換時機 | 適用對象 |
|------|----------|----------|----------|
| 介面多語 | `lang/` 語系檔 | `App::setLocale()` | 固定 UI 文字 |
| 網址多語 | URL 第一段 | `SetLocale` middleware | 每次 request |
| 內容多語 | `xxx_translations` 表 | `$model->name` 自動查 locale | 動態資料 |

三者由 `SetLocale` middleware 串聯：middleware 根據 URL 設定 `App::setLocale()`，之後 `__()` 和 `HasTranslation` 都自動使用對應語系。
