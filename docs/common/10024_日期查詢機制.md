## 一、一句話規範（快速參考）

> Model 把日期欄位寫進 `$casts` → 控制器只要 `OrmHelper::prepare()` → 前端送 `filter_<date_column>` 自動套智慧日期解析（單日 / 區間 / 比較運算子）。控制器不需要額外 `if ($request->filled(...))` 加日期 where 條件。

| 元素 | 動作 |
|------|------|
| Model `$casts` | `'shipping_date' => 'date'`（或 datetime / immutable_date / immutable_datetime / `date:Y-m-d`） |
| 控制器 | `$filter_data = $this->filterData($request, ['filter_shipping_date']); OrmHelper::prepare($query, $filter_data);` |
| 前端 input | `<input name="filter_shipping_date" placeholder="如 20260425 或 20260401-20260430">` |
| URL | `?filter_shipping_date=20260401-20260430` → `WHERE shipping_date BETWEEN '2026-04-01' AND '2026-04-30'` |

## 二、智慧日期語法

`DateHelper::applySmartFilter()` 接受的語法，皆對應到 Eloquent `whereDate` / `whereDate >= … AND whereDate <=` 語意，**不字串拼 SQL**。

### 2.1 單日

| 輸入 | 解析結果 | 說明 |
|------|----------|------|
| `2026-04-25` | `2026-04-25` | 標準格式 |
| `2026/04/25` | `2026-04-25` | `/` 自動轉 `-` |
| `26-04-25` | `2026-04-25` | 2 位數年自動補 `20YY` |
| `20260425` | `2026-04-25` | 8 位數無分隔 |
| `260425` | `2026-04-25` | 6 位數無分隔（`YYMMDD`） |

> 月、日的位數允許 1~2 碼（`2026-4-5` 也合法），但 8/6 位數連續格式必須是嚴格的 `YYYYMMDD` / `YYMMDD`，月日各 2 碼。

### 2.2 區間

| 輸入 | 解析結果 | 等價 SQL |
|------|----------|-----------|
| `20260401-20260430` | `2026-04-01` ~ `2026-04-30` | `BETWEEN` |
| `260501-260531` | `2026-05-01` ~ `2026-05-31` | 同上 |
| `2026-04-01-2026-04-30` | `2026-04-01` ~ `2026-04-30` | 長格式以單一 `-` 連接，regex 仍可拆 |

### 2.3 比較運算子（前綴）

| 輸入 | 等價 SQL |
|------|-----------|
| `>20260101` | `whereDate(col, '>', '2026-01-01')` |
| `>=20260101` | `whereDate(col, '>=', '2026-01-01')` |
| `<20260101` | `whereDate(col, '<', '2026-01-01')` |
| `<=20260101` | `whereDate(col, '<=', '2026-01-01')` |
| `=20260101` | `whereDate(col, '=', '2026-01-01')` |

長前綴（`>=` / `<=`）regex 內優先比對，避免 `>` 誤吞掉 `>=` 後半段。

### 2.4 解析失敗 — silent no-op

| 輸入 | 行為 |
|------|------|
| `''`、`null`、`abc` | 不套任何 `where` 條件（=不過濾）|
| `2026-13-01`、`20260230` | `checkdate()` 不過 → silent no-op |
| 半完整輸入（`2026-04`）| 不符合任何 regex → silent no-op |

> 解析失敗一律 **silent**，不擲例外、不污染 query。需要嚴格校驗請在 Validation 層處理。這設計符合「使用者邊打邊改」的搜尋體驗 — 還沒打完的字串不應該整頁壞掉。

## 三、自動偵測機制（OrmHelper × Model `$casts`）

`OrmHelper::applyFilters()` 內部對每個 `filter_xxx` 參數做下面這個分流：

```php
// 主表欄位（排除翻譯欄位）
if (in_array($column, $tableColumns) && !in_array($column, $translatedAttributes)) {
    // filter_ + date/datetime cast → 智慧日期解析
    if (str_starts_with($key, 'filter_') && self::isDateCastColumn($model, $column)) {
        DateHelper::applySmartFilter($query, $column, (string) $value);
    } else {
        self::filterOrEqualColumn($query, $key, $value);
    }
}
```

判斷邏輯 `isDateCastColumn()`：

```php
protected static function isDateCastColumn(Model $model, string $column): bool
{
    $cast = $model->getCasts()[$column] ?? null;
    if (! $cast) {
        return false;
    }
    $type = strtolower(strtok((string) $cast, ':'));
    return in_array($type, ['date', 'datetime', 'immutable_date', 'immutable_datetime'], true);
}
```

被視為日期的 cast 型別：

| cast 寫法 | 是否觸發智慧日期路由 |
|-----------|--------------------|
| `'shipping_date' => 'date'` | ✅ |
| `'created_at' => 'datetime'` | ✅ |
| `'effective_date' => 'date:Y-m-d'` | ✅（取冒號前的型別名） |
| `'closed_at' => 'immutable_datetime'` | ✅ |
| `'price' => 'decimal:2'` | ❌（不在 date 家族） |
| `'is_active' => 'boolean'` | ❌ |
| **沒寫進 `$casts`** | ❌（fallback 走一般 `filter_*` 模糊比對） |

> **重要**：欄位實際是 `DATE` / `DATETIME` 也好，**但沒寫進 `$casts`** 就**不**會被路由到智慧日期。`$casts` 是 source of truth，這也讓你可以**主動關閉**某個日期欄位的智慧解析（移除 cast 或改成 string cast）。

## 四、用法範例

### 4.1 最簡情境（一個日期欄位）

```php
// app/Models/Sales/Order.php
class Order extends Model
{
    protected function casts(): array
    {
        return [
            'shipping_date' => 'date',
            'created_at'    => 'datetime',
        ];
    }
}

// app/Portals/Ocadmin/Modules/Sales/Order/OrderController.php
protected function getList(Request $request): string
{
    $query = Order::query();

    $filter_data = $this->filterData($request, [
        'filter_shipping_date',
        'equal_status',
    ]);
    $filter_data['sort']  = $request->query('sort', 'shipping_date');
    $filter_data['order'] = $request->query('order', 'desc');

    OrmHelper::prepare($query, $filter_data);   // ← 一行打通
    $orders = OrmHelper::getResult($query, $filter_data);
    // ...
}
```

對應的 view：

```blade
<input type="text" name="filter_shipping_date"
       value="{{ request('filter_shipping_date') }}"
       placeholder="2026-04-25 / 20260425 / 20260401-20260430"
       class="form-control">
```

支援的 URL 範例：

```
?filter_shipping_date=20260425              → 該日
?filter_shipping_date=20260401-20260430     → 4 月區間
?filter_shipping_date=>=20260101            → 從元旦起
?filter_shipping_date=<20260101             → 元旦前
```

### 4.2 起訖兩個欄位（仍可走自動，但常見手動處理）

如果是 `date_from` / `date_to` **兩個獨立輸入**對應**同一個 `work_date` 欄位**的「起訖」UI，常見作法仍寫在控制器：

```php
if ($request->filled('filter_date_from')) {
    $query->where('work_date', '>=', $request->filter_date_from);
    unset($filter_data['filter_date_from']);
}
if ($request->filled('filter_date_to')) {
    $query->where('work_date', '<=', $request->filter_date_to);
    unset($filter_data['filter_date_to']);
}
```

這場景**不是**智慧日期的目標 — 智慧日期是「一個輸入框接受多種格式」的場景。兩種寫法不互相取代，搭配使用即可。

### 4.3 多日期欄位混用

```php
class Invoice extends Model
{
    protected function casts(): array
    {
        return [
            'invoice_date' => 'date',
            'due_date'     => 'date',
            'paid_at'      => 'datetime',
        ];
    }
}

// 三個欄位都自動支援智慧日期
$filter_data = $this->filterData($request, [
    'filter_invoice_date',
    'filter_due_date',
    'filter_paid_at',
]);
OrmHelper::prepare($query, $filter_data);
```

## 五、與 `equal_xxx` 的差異對照

| 維度 | `filter_xxx`（智慧日期適用） | `equal_xxx`（不適用） |
|------|----------------------------|--------------------|
| 觸發條件 | key 以 `filter_` 開頭 **且** Model 有 date/datetime cast | key 以 `equal_` 開頭 |
| 解析語法 | 單日 / 區間 / 比較運算子 / 多種格式 | 字面相等 — 必須是 query 可直接吃的格式 |
| SQL 形態 | `whereDate(col, op, parsed)` 或 `whereDate >= AND whereDate <=` | `where(col, '=', value)` |
| 用途定位 | 使用者自由輸入的「搜尋框」 | 由下拉選單 / 隱藏欄位餵入的精確過濾 |
| 解析失敗行為 | silent no-op（不過濾） | 直接 `where col = <非法值>`，會撈不到資料但不報錯 |

簡言之：**`filter_` 是給人打字的，`equal_` 是給 JS 餵 ID 的**。日期欄位若用 dropdown / picker 餵已標準化的 `YYYY-MM-DD`，可直接用 `equal_xxx` 走精確比對，跳過智慧日期路由。

## 六、實作位置

### 6.1 檔案結構

```
app/Helpers/Classes/
├── DateHelper.php          # parse() / applySmartFilter()
└── OrmHelper.php           # applyFilters() 內 isDateCastColumn() 自動分流
```

### 6.2 `DateHelper` 公開方法

| 方法 | 簽名 | 用途 |
|------|------|------|
| `parse()` | `parse(?string $input): ?string` | 寬鬆解析多種格式為 `Y-m-d`；失敗回 `null` |
| `applySmartFilter()` | `applySmartFilter(Builder $query, string $column, ?string $input): void` | 將 `$input` 解析後套到 `$query` 的 `$column`；失敗 silent no-op |

### 6.3 對外保證

- 內部一律走 Eloquent `whereDate`，不字串拼 SQL（避免 injection）
- 解析失敗 silent no-op，不擲例外
- 自動偵測機制不需控制器顯式呼叫 `DateHelper`，由 `OrmHelper::prepare()` 觸發

### 6.4 衍生 branch 對齊原則

衍生 branch 的 `DateHelper.php` 與本範本保持 namespace 與內容 byte-level 一致。`OrmHelper.php` 的 `isDateCastColumn()` 自動路由分支需配合 `DateHelper` 存在才能啟用；衍生 branch 若 `OrmHelper` 落後於規範，以本文件為基準對齊。

## 七、設計取捨與安全性

### 7.1 為何採「Model `$casts` 自動偵測」而非手動標註

- **Single source of truth**：Eloquent 已強制要求日期欄位寫 cast 才能拿到 Carbon 物件，沒有第二個地方需要維護
- **零成本上線**：新增日期欄位的 Model 只要把 cast 寫對，列表搜尋自動具備智慧日期能力，控制器無需改動
- **可主動關閉**：不想要智慧日期路由時，把 cast 改成 `string` 或從 `$casts` 移除即可，不需要在 OrmHelper 加例外清單

### 7.2 為何走 `whereDate` 而不是 `where`

- `where('col', '>=', '2026-04-01')` 對 `DATETIME` 欄位會吃 `'2026-04-01 00:00:00'` 的隱式時間，行為依資料庫而異
- `whereDate('col', '>=', '2026-04-01')` 由 Laravel 統一處理成 `DATE(col) >= '2026-04-01'`，跨欄位型別行為一致

### 7.3 為何 silent no-op

搜尋是漸進式輸入，使用者邊打邊看結果是常態。`2026-` 半完成的輸入不該整頁壞掉或彈錯。需要嚴格校驗（如表單送出時必須是合法日期）請在 Validation 層處理，與本機制分工。

### 7.4 安全性

`whereDate()` 內部會走 PDO bind 參數，輸入經 `checkdate()` 與 `sprintf` 重新格式化後才入 query；運算子也由 regex 白名單限制為 `>= / <= / > / < / =`，無 SQL injection 風險。
