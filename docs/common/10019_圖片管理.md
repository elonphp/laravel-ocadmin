# 10019 圖片管理（Image Management）

`storage/app/public/` 下的圖片管理分**兩大條路線**，各自獨立頂層 root，picker 與系統圖完全平行隔離；`cache/` 是不可數 mass noun（單數），在頂層鏡像所有原圖路徑作為共用縮圖快取。

```
storage/app/public/
├── images/       ← picker root（複數，使用者管理領域）
├── products/     ← 系統專用：商品圖
├── banners/      ← 系統專用：banner（系統強制管理）
└── cache/        ← 不可數，單數
    ├── images/...
    ├── products/...
    └── banners/...
```

---

## 一、使用者圖片管理（picker root：`images/`）

picker 是後台共用 Bootstrap Modal「選擇圖片」，使用者自由瀏覽 / 上傳 / 建資料夾 / 刪除 `images/` 子樹下任何位置的檔案。表單欄位（如 banner 引用、選項值圖、CKEditor 插入圖）透過 `data-oc-toggle="image"` 叫出 picker，使用者點選後路徑回填到 hidden input。**picker 僅作用於 `images/` 一棵樹**，不會碰到 `products/` / `banners/`。

## 二、系統專用圖片管理（system-managed roots）

某些業務的圖片（如商品圖、banner）有 owner row、需強制重新命名、生命週期跟著 owner，**不適合**塞進 picker 自由管理。系統依資料庫 row 強制命名與組織子樹（如 `products/{product_id}/images/{product_id}_{rand7}.{ext}`），每類業務各自佔頂層一個 root，picker 看不到也碰不到。詳細骨架見後文第二章。

# 第一章：使用者圖片管理（picker）

## 1-1. ImageLibrary 來源與改良

`app/Libraries/ImageLibrary.php` 參考自 OpenCart 4.x（`system/library/image.php`），改良點：

- **移除未使用方法**：OpenCart 原版包含 `crop()` / `watermark()` / `rotate()` / `filter()` / `text()` / `merge()` / `html2rgb()`，在 OpenCart 4.x 自身原始碼中皆無呼叫，屬於死碼。本系統僅保留實際使用的 `resize()` 與 `save()`。
- **PNG gAMA 修復**：新增 `cleanImage()`，偵測 PNG 的 gAMA chunk 並重建像素，解決跨瀏覽器色彩異常。
- **透明背景處理**：`save()` 針對 PNG / WEBP 加 `imagealphablending` + `imagesavealpha`，確保透明背景正確儲存。
- **PHP 8.0+ 適配**：以 `unset()` 取代已 deprecated 的 `imagedestroy()`。

## 1-2. Storage 路徑

`php artisan storage:link` 建立 symlink：`public/storage` → `storage/app/public`。Windows 上 Laravel 用 `mklink /D`，需以**系統管理員**身份執行 terminal。

picker root：`storage/app/public/images/`
公開 URL：`https://domain/storage/images/{relative-path}/{file}.{ext}`

> `public/assets/ocadmin/image/no_image.png` 作為表單預覽 placeholder。
> `storage/app/public/images/no_image.png` 供 ImageLibrary PNG 處理 fallback 使用。

## 1-4. 核心元件

### ImageHelper（picker + system-managed 共用）

`app/Helpers/Classes/ImageHelper.php`，靜態方法 `resize()`：

```php
$thumbUrl = ImageHelper::resize('images/categories/main.jpg', 100, 100);
// → https://domain/storage/cache/images/categories/main-100x100.jpg
```

- 接收相對 `storage/app/public/` 的 path，產縮圖到 `cache/{原路徑}-{W}x{H}.{ext}` 並回 URL
- mtime 比對：原圖 replace 後 mtime 變新自動失效重產
- `realpath()` 路徑安全檢查防目錄遍歷
- **不限定 picker root**：`images/` / `products/` / `banners/` 任一 root 下的 path 都吃，cache 鏡像對應原路徑

### ImageManagerController（picker only）

`app/Portals/Ocadmin/Core/Controllers/ImageManagerController.php`：

| 方法 | HTTP | 路由 | 說明 |
|------|------|------|------|
| `index()` | GET | `/common/image-manager` | Modal 外殼 HTML（帶 target / thumb 參數） |
| `list()` | GET | `/common/image-manager/list` | 檔案瀏覽器 partial（目錄 / 檔案、分頁） |
| `upload()` | POST | `/common/image-manager/upload` | 檔案上傳（JSON 回應） |
| `folder()` | POST | `/common/image-manager/folder` | 建立資料夾（JSON 回應） |
| `delete()` | POST | `/common/image-manager/delete` | 刪除檔案 / 資料夾（JSON 回應） |

核心邏輯：

- **base 路徑**：`storage_path('app/public/images/')`（picker root，複數）
- `list()`：glob 掃描；每頁 16 筆；可搜尋 / 排序（名稱、大小、日期）
- 縮圖透過 `ImageHelper::resize()` 產生
- `upload()`：白名單副檔名（jpg/jpeg/png/gif/webp/ico）+ MIME 驗證 + 檔名長度（4–255）+ 上傳尺寸 cap（見 §三-2）
- `folder()`：在 `images/` 子樹建立子目錄，名稱長度 3–128
- `delete()`：遞迴刪除；安全檢查：所有路徑先 `realpath()` 再驗 prefix 必須以 picker root 開頭——任何企圖叫 picker 走進 `products/` / `banners/` 的 request 都會被擋

## 1-5. Views

`common/image-manager/index.blade.php`（Modal 外殼）載入後立即 AJAX 呼叫 `list` 路由填充 `.modal-body`。`list.blade.php` 支援：

- **Grid view**：網格佈局 `row-cols-sm-3 row-cols-lg-4`，目錄以資料夾圖示、圖片以縮圖
- **List view**：表格佈局，欄位 checkbox / 預覽 / 檔名 / 大小 / 修改日期，表頭可 asc / desc 排序
- 視圖切換按鈕（小圖 / 列表）以 `localStorage('imgmanager_view')` 持久化
- 工具列：上一層、重新整理、上傳、新增資料夾、刪除、搜尋
- 底部分頁

## 1-6. 路由

```php
use App\Portals\Ocadmin\Core\Controllers\ImageManagerController;

Route::prefix('image-manager')->name('image-manager.')->group(function () {
    Route::get('/', [ImageManagerController::class, 'index'])->name('index');
    Route::get('/list', [ImageManagerController::class, 'list'])->name('list');

```

完整路由名：`lang.ocadmin.common.image-manager.*`。

## 1-7. 前端觸發機制

`public/assets/ocadmin/javascript/common.js` 監聽 `[data-oc-toggle='image']`，從 `#imgmanager-url` hidden input 取得 URL，AJAX 載入 Modal：

```javascript
$(document).on('click', '[data-oc-toggle="image"]', function () {
    $('#modal-image').remove();
    var url = $('#imgmanager-url').val()
        + '?target=' + encodeURIComponent($(this).attr('data-oc-target'))
        + '&thumb=' + encodeURIComponent($(this).attr('data-oc-thumb'));
    $.get(url, function (html) {
        $('body').append(html).find('#modal-image').modal('show');
    });
});
```

使用 picker 的表單頁面 layout 內含 hidden input：

```html
<input type="hidden" id="imgmanager-url" value="{{ route('lang.ocadmin.common.image-manager.index') }}">
```

## 1-8. 表單整合：picker 欄位範式

任何欄位需要使用者選圖（如 banner 表單的 banner image、選項值圖），都用同一組 `data-oc-toggle` 機制：

```blade
<div class="image">
    <img src="{{ $thumb ?? $defaultThumb }}" id="thumb-image-{{ $key }}" class="img-thumbnail" style="max-width:100px;">
    <input type="hidden" name="image" value="{{ $value }}" id="input-image-{{ $key }}">
    <div class="btn-group mt-1">
        <button type="button" data-oc-toggle="image"
                data-oc-target="#input-image-{{ $key }}"
                data-oc-thumb="#thumb-image-{{ $key }}"
                class="btn btn-primary btn-sm"><i class="fa-solid fa-pencil"></i></button>
        <button type="button" data-oc-toggle="clear"
                data-oc-target="#input-image-{{ $key }}"
                data-oc-thumb="#thumb-image-{{ $key }}"
                class="btn btn-warning btn-sm"><i class="fa-solid fa-trash-can"></i></button>
    </div>
</div>
```

回填邏輯（modal 內）：

```javascript
$('{{ $thumb }}').attr('src', imgSrc);     // 更新預覽
$('{{ $target }}').val(pathVal);           // 寫入隱藏 input（含 'images/' 前綴）
```

回填的 path 永遠含 `images/` 前綴（相對 `storage/app/public/`），表單 save 時直接存 DB；後端讀取時用 `asset('storage/' . $path)` 取得公開 URL。

## 1-9. 資料流程

```
[Edit] 按鈕 (data-oc-toggle="image")
  └─→ common.js GET /common/image-manager?target=...&thumb=...
       └─→ ImageManagerController::index() → Modal HTML
            └─→ Modal append + show, AJAX GET /common/image-manager/list
                 └─→ ImageManagerController::list() → glob storage/app/public/images/
                      └─→ ImageHelper::resize() 縮圖 → list.blade.php
                           └─→ user 點圖 → 寫入 hidden input + 更新預覽
                                └─→ form save → DB 存 'images/...' 相對路徑
```

## 1-10. 語系檔

`lang/{locale}/admin/common/image-manager.php` 提供 `zh_Hant` 與 `en`：標題、按鈕（上一層 / 重新整理 / 上傳 / 新增資料夾 / 刪除 / 搜尋 / 小圖 / 列表）、欄位、錯誤訊息、操作成功訊息。group 前綴 `admin/` 由 `OcadminController::getLang()` 自動補上（子類 `setLangFiles()` 只回 `['common/image-manager']`）。

# 第二章：系統專用圖片管理（system-managed roots）

## 2-1. 設計準則：何時開新 root

下列訊號任一命中即考慮獨立 root，否則放 picker `images/{subdir}/` 即可：

| 訊號 | 說明 |
|---|---|
| 圖片**有 owner row**（FK 到某張表） | owner 刪除時要 cascade 清檔 |
| 檔名**需系統強制重新命名**（如加 owner_id 前綴防孤兒） | 跟 picker 自由命名不相容 |
| 不希望使用者**手動刪除 / 重命名 / 搬移** | picker 賦予的自由與業務不一致 |
| 跨 row 命名衝突需自動解決（rand suffix 等） | 系統介入產檔名 |

衍生專案常見的兩個 root：

- **`products/{product_id}/images/`** — 商品圖（multi-image），商品刪除時整資料夾 cascade 清除
- **`banners/{banner_id}/`** — banner（系統強制管理檔名與生命週期）

## 2-2. 與 picker root 平行隔離

| 對比項 | picker root（`images/`） | system-managed roots |
|---|---|---|
| 位置 | `storage/app/public/images/` | `storage/app/public/{products,banners,...}/` |
| 命名 | 使用者自選原檔名 | 系統強制（通常 `{owner_id}_{rand7}.{ext}`） |
| 子樹組織 | 使用者自由建資料夾 | 系統依 row 規則組織（如 `{id}/images/`） |
| 生命週期 | 使用者手動 / 永久 | 跟 owner row 綁定，cascade 清除 |
| `ImageManagerController` 是否能操作 | ✅ | ❌（picker 看不到） |
| 表單 UI | 共用「選擇圖片」Modal | 業務模組各自 per-row API + tab |

雙方完全分離，**不需要 hardcoded 排除**：picker `glob` 從 `images/` 起掃，根本不會掃到別處。

## 2-3. 標準骨架（以 Product 商品圖為具體例子）

下面以**商品圖**為例展示具體實作骨架。其他業務（banner / category / brand 等）開新 system-managed root 時平行展開即可（把 `Product` 換成對應 owner 名稱、`products/` 換成對應 root 名稱、`ctl_product_images` 換成對應子表）。

> ocadmin 本身不實作這些 controller / table，僅提供骨架供衍生專案參照。

### 2-3-1. Schema

新建 owner 子表 `ctl_product_images`（每個 system-managed root **都要建一張這樣的子表**）：

| 欄位 | 用途 |
|---|---|
| `id` | bigint PK |
| `product_id` | FK → `ctl_products.id` cascadeOnDelete |
| `path` | 相對 `storage/app/public/` 的完整路徑（如 `products/123/images/123_xK7p2qa.jpg`） |
| `original_filename` | 上傳時原檔名（管理面顯示用，不參與 storage 命名） |
| `mime_type` / `size_bytes` / `width` / `height` | 上傳時抓進 DB |
| `sort_order` | 顯示順序（小 → 大） |
| `is_default` 等業務旗標 | 業務需求；每個 owner 至多一張為 true，由 Observer 維護 |
| `uploaded_by` | FK → `users.id` nullOnDelete |
| `created_at` / `updated_at` | timestamps |

owner 主表（`ctl_products`）保留 `image` 欄位作為 **denormalized 預設圖路徑**：列表 / 摘要場景直接讀，不需 join 子表。

### 2-3-2. 重新命名存檔

```php
$ext = strtolower($file->getClientOriginalExtension());
$filename = "{$product->id}_" . Str::random(7) . ".{$ext}";
$dir = "products/{$product->id}/images";
$path = $file->storeAs($dir, $filename, 'public');

// 上傳完用 ImageLibrary cap 到全域 box
$this->capDimensions(Storage::disk('public')->path($path));
```

設計取捨：

- **`{product_id}_` 前綴**：即使檔案被誤搬出資料夾仍認得屬誰；方便寫 cleanup 腳本掃孤兒
- **`{rand7}` suffix**：`Str::random(7)` = base62 約 3.5 兆組合，避免同 product 連續上傳衝突；UUID 太長
- **副檔名小寫**

### 2-3-3. 路由與 Controller 位置

新建 Controller `app/Portals/Ocadmin/Modules/Catalog/Product/Image/ProductImageController.php`（路徑遵循 Module 階層；其他業務照各自模組路徑放，如 banner 的 `Modules/Marketing/Banner/Image/BannerImageController.php`）。

system-managed 圖**不依附 parent form save**，每個 row 動作獨立打 API：

```php
// app/Portals/Ocadmin/routes/ocadmin.php（catalog products group 內）
Route::prefix('{product}/images')->name('image.')->group(function () {
    Route::post('/',                 [ProductImageController::class, 'store'])->name('store');
    Route::patch('/{image}/replace', [ProductImageController::class, 'replace'])->name('replace');
    Route::patch('/{image}',         [ProductImageController::class, 'update'])->name('update');
    Route::delete('/{image}',        [ProductImageController::class, 'destroy'])->name('destroy');
});
```

理由：multipart 不適合塞進 parent form ajax submit；每張獨立上傳，失敗不影響其它已成功的；`replace` 時舊檔的清理必須立即發生（避免廢棄檔累積）。

### 2-3-4. Observer：cascade 與 default 維護

新建 `ProductImageObserver`（觀察 `ProductImage` model）：

```php
saved(ProductImage $image):
    if (is_default) → product->update(['image' => path])

deleted(ProductImage $image):
    Storage::disk('public')->delete(path)
    if (was default && product still has images):
        next = product->images()->first()
        next->update(['is_default' => true])  // saved hook 同步 ctl_products.image
    elseif (was default):
        product->update(['image' => null])
```

Product 整支被刪除時，另在 `ProductCacheObserver::deleted` 整資料夾清掉：

```php
Storage::disk('public')->deleteDirectory("products/{$product->id}");
```

放 `deleted`（不是 `deleting`）避免事務 rollback 後檔已先刪。

### 2-3-5. UI：per-row 表格 tab

商品 form 加一個「圖片管理」tab，表格化（一列一張圖）：順序 input + 縮圖 + per-row「替換 / 刪除」按鈕，footer「新增」按鈕；每動作獨立 API 立即生效。

Product 未存檔（create 模式）時整 tab 必須 disable —— 檔名規則需要 `product_id` 前綴。Product 儲存後 form 重新渲染（既有 `replace_url` 機制），tab 即解鎖。

完整實作細節（schema 完整欄位定義、ETL、API 輸出格式、前台 gallery）由衍生專案自行擴充。

# 第三章：共用機制（picker + system-managed）

## 3-1. 上傳大小三層限制

由硬到軟：

| 層 | key / 位置 | 行為 |
|---|---|---|
| 1. **php.ini**（OS 硬限制） | `upload_max_filesize` / `post_max_size` | 超過 request 進不到 Laravel；要 server admin 編 php.ini |
| 2. **`config_file_max_size`** sys_settings（DB） | 預設 5 MB | picker 與系統圖共用；admin 在後台 settings 頁可調 |
| 3. **Laravel validation rule**（per-controller） | inline `max:` | 動態取自 sys_settings；不寫死 |

> ⚠️ 三邊**從上往下**會被前一層先擋；server admin 部署時要保證 php.ini ≥ `config_file_max_size`，否則 admin 在後台調再大都沒用（檔案先被 php 擋掉）。Laravel 端用 `'max:' . config('settings.config_file_max_size') * 1024` 動態組規則。

## 3-2. 全域上傳尺寸 cap（resize）

上傳完存檔後，server 立即用 `ImageLibrary` 把原圖縮到全域上限 box 內（保持比例），設定取自 `sys_settings`：

| key | 預設 | 說明 |
|---|---|---|
| `config_image_width` | 2048 | 全域上傳上限寬 |
| `config_image_height` | 2048 | 全域上傳上限高 |

picker upload 與 system-managed upload **都套用**，全站 storage 不會出現怪物大圖。User 傳 8000×6000 進來，存檔後是 2048×1536（保持比例）。實作在 `ImageManagerController::capDimensions()`，system-managed controller 共用此邏輯（或抽 trait）。

## 3-3. 縮圖 cache（`cache/` 鏡像）

`storage/app/public/cache/` 是頂層目錄（不可數 mass noun，單數），**鏡像所有原圖路徑**作為共用縮圖快取：

```
images/{path}/{file}.jpg      → cache/images/{path}/{file}-{W}x{H}.jpg
products/{id}/images/x.jpg    → cache/products/{id}/images/x-{W}x{H}.jpg
banners/{id}/y.png            → cache/banners/{id}/y-{W}x{H}.png
```

`ImageHelper::resize($path, W, H)` 統一處理：第一次呼叫產縮圖到 cache，後續呼叫直接回 URL（mtime 自動失效）。

衍生業務按需求調用，不需另寫快取機制。例如商品 detail 用兩個尺寸：

| key | 預設 | 用途 |
|---|---|---|
| `config_product_image_thumb_width` / `height` | 300 | 縮圖列尺寸 |
| `config_product_image_popup_width` / `height` | 1080 | 主圖區 + lightbox 共用 |

cache 不需備份，可隨時 `rm -rf cache/` 全清重產。

# 第四章：安全

- **路徑穿越**：所有路徑運算前先 `realpath()`，再驗 prefix 必須以對應 root 開頭（picker 限 `images/`、system-managed 限 `products/{id}/images/` 等）
- **白名單副檔名 / MIME**：picker 接受 `jpg / jpeg / png / gif / webp / ico`；system-managed 通常更窄（`jpg / jpeg / png / webp`），不收 SVG（防內嵌 script XSS）
- **檔名清洗**：picker 保留使用者原檔名但 `preg_replace('/[\/\\\\?%*:|"<>]/', '', basename(...))`，長度 4–255
- **system-managed 重新命名**：完全由系統生成檔名，無 user 提供成分；防路徑穿越無懸念
- **picker root 隔離**：`ImageManagerController` 的 `list()` / `delete()` / `upload()` 都從 `images/` 起算 base，不可能波及 `products/` / `banners/`
