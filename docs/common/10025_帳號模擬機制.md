## 一、概述

### 1.1 功能目標

提供 `super_admin` 在後台「以指定使用者身分檢視」的能力（**唯讀**，不可寫入），用於：

1. 重現使用者回報的畫面 / 權限問題（「我看到的選單跟你不一樣」）
2. 驗證新權限規則對特定角色的實際呈現

### 1.2 唯讀設計的考量

| 為何不允許「以他身分寫入」 | 說明 |
|---|---|
| 責任歸屬 | 寫入會混淆「真正操作者是誰」，事後 audit 難以判斷 |
| 業務風險 | HR / 薪資 / 訂單等敏感資料誤觸成本高 |
| 替代方案 | 需要代操的場景應走正規操作員權限（如 `hr_manager`），留下真實操作者身分 |

本機制定位為「以他身分『看』」，不含「以他身分『做』」。

### 1.3 與權限機制的關係

`super_admin` 由 [`10007_權限機制`](10007_權限機制.md) 的 `Gate::before` 無條件放行所有權限。模擬期間 `auth()->user()` 切到 target，所有權限檢查改以 target 身分判定 — 包含 target 看不到的選單、權限不足的 403 都會如實重現，這正是本機制的核心價值。

## 二、與其他登入機制的分工

| 機制 | 用途 | 可用環境 | 對象 |
|---|---|---|---|
| Seeded 測試帳號 | 日常開發、單元測試 | local / staging | 開發者本人 |
| `dev login`（POST `/dev/login`） | CLI / curl 測試 | local 限定 | 開發者本人 |
| **本機制（Impersonate）** | 重現問題、權限驗證（唯讀） | local / staging / production | `super_admin` → 任意使用者（除其他 `super_admin`） |

三者**並存不衝突**：dev login 是 CLI 短路，僅 `APP_ENV=local`；本機制是 production-capable 的後台工具。

## 四、資料模型

設計原則：**只新增本機制的表，不污染框架核心表**（`request_logs` 不動，跨環境保持一致）。

### 4.1 新增表：`impersonation_sessions`

建議放 `sysdata` 連線（與 `request_logs` 同連線，便於審計查詢做時間區間 JOIN）。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | bigint PK | |
| `session_uuid` | char(36), unique | 對外辨識用，避免暴露自增 id |
| `impersonator_user_id` | bigint, index | 真實 admin |
| `target_user_id` | bigint, index | 被模擬者 |
| `started_at` | datetime, index | |
| `ended_at` | datetime, nullable | NULL 表示仍在模擬中 |
| `end_reason` | varchar(32), nullable | 結束原因（見 §4.3） |
| `reason_note` | varchar(255) | 啟動時填的「為何要模擬」（必填，至少 5 字）— **僅 admin / super_admin 看，不給 target 看** |
| `revoked_by_user_id` | bigint, nullable | 若被強制終止，記錄是誰終止的；自願 stop / timeout 為 NULL |
| `client_ip` | varchar(45), nullable | 啟動時的 IP |
| `user_agent` | text, nullable | 啟動時的 UA |
| `created_at` / `updated_at` | timestamps | |

### 4.2 索引

| 索引 | 用途 |
|---|---|
| `(impersonator_user_id, started_at)` | 「某 admin 最近模擬過誰」 |
| `(target_user_id, started_at)` | 「某員工被誰模擬過」（員工歷史頁用） |
| `(impersonator_user_id, ended_at)` | 「某 admin 是否有 active session」（雙向鎖判斷） |
| `(target_user_id, ended_at)` | 「某員工是否正被模擬」（target blocked 頁判斷） |
| `(ended_at)` | 所有 active session 列表用 |

### 4.3 `end_reason` 值域

| 值 | 觸發場景 |
|---|---|
| `manual_exit` | admin 自願按「結束模擬」按鈕 |
| `timeout` | 超過 `config('impersonate.timeout_minutes')` 無活動 |
| `admin_logout` | admin 整體登出系統 |
| `target_disabled` | 被模擬者帳號被停權（is_active = false） |
| `force_revoke` | admin 自己從 blocked 頁強制終止 |
| `revoked_by_other` | 其他 super_admin 從歷史頁終止 |

### 4.4 request_logs 不動

模擬期間 `request_logs.user_id = target_user_id`（`Auth::login($target)` 的自然結果）。審計靠 `impersonation_sessions` 的時間區間反推：

```sql
-- 「這個 admin 模擬期間做了什麼」
SELECT r.*, s.session_uuid, s.reason_note
  FROM request_logs r
  JOIN impersonation_sessions s
    ON r.user_id = s.target_user_id
   AND r.created_at >= s.started_at
   AND (s.ended_at IS NULL OR r.created_at <= s.ended_at)
 WHERE s.impersonator_user_id = ?
 ORDER BY r.created_at;
```

**前提**：模擬期間 `request_logs.user_id = target` 的請求**確定來自 admin**（target 自己沒在用）— 這由下節「雙向鎖」保證。

## 五、雙向鎖

設計精神：**透明公開 + 審計正確**。

模擬期間，admin（impersonator）與 target 兩邊的所有 session 同時被清空、雙方從別處嘗試重新登入皆被攔截：

- **admin 端**：避免「admin 與被模擬者並存」的曖昧狀態，保證審計查詢正確
- **target 端**：員工立即知道「我正被模擬」，符合透明公開政策；且確保審計期間 `request_logs` 確定只來自 admin

### 5.1 啟動時：強制登出 admin + target 兩邊所有 session

不只「當前瀏覽器 tab」— 雙方在別瀏覽器、別電腦的 session 全清。

```php
// ImpersonationService::start() 內
$currentSessionId = Session::getId();

DB::table('sessions')
    ->whereIn('user_id', [$admin->id, $target->id])
    ->where('id', '!=', $currentSessionId)  // 排除當前 session
    ->delete();

// 接著 Auth::login($target) 把當前 session 切到被模擬者
Auth::login($target);
```

**影響 target 體驗**：target 員工若正在用系統，下次 request 會因 session 失效被導向登入頁；嘗試重登時看到 blocked 頁。target 未存的工作（填寫中表單）可能丟失，blocked 頁明確提示。

> 未來可考慮（不在本期）：模擬中暫存 target session 資料，模擬結束後恢復。複雜度高。

### 5.2 模擬中：admin 嘗試重新登入 → 攔截

OAuth callback 完成、`Auth::login` 之前先檢查：

```php
// AccountsOAuthController::callback() 內
$activeAsImpersonator = $impersonate->findActiveAsImpersonator($user);
if ($activeAsImpersonator) {
    Session::put('impersonate.blocked_attempt', [
        'role'         => 'impersonator',
        'user_id'      => $user->id,
        'session_uuid' => $activeAsImpersonator->session_uuid,
        'access_token' => $accessToken->getToken(),   // 緊急解鎖後不必再走 OAuth
        'verified_at'  => now()->timestamp,
    ]);
    return redirect()->route('impersonate.blocked');
}
```

admin blocked 頁顯示「您正在模擬中（從 X 時起、原因 Y）」+「強制終止模擬並登入」按鈕。

### 5.3 模擬中：target 嘗試重新登入 → 攔截

同 callback 攔截點再加一個查詢：

```php
$activeAsTarget = $impersonate->findActiveAsTarget($user);
if ($activeAsTarget) {
    Session::put('impersonate.blocked_attempt', [
        'role'         => 'target',
        'user_id'      => $user->id,
        'session_uuid' => $activeAsTarget->session_uuid,
        'verified_at'  => now()->timestamp,
    ]);
    return redirect()->route('impersonate.blocked');
}
```

target blocked 頁顯示「您的帳號正由管理員-{admin name} 模擬使用」+ 開始時間 + 預計 timeout 時間。

**target 端的差異**：

- **無「強制終止」按鈕** — 員工不能取消 admin 的 audit 動作
- **不顯示 `reason_note`** — admin 啟動時的「為何要模擬」可能含敏感字眼（例：「員工反映薪水算錯」），給該員工看反而尷尬

要中止 target 端的鎖只能：admin 自己 stop / 其他 super_admin force-revoke / 等 timeout。

### 5.4 為什麼 `Session::put('impersonate.blocked_attempt', ...)`

OAuth callback 階段已驗證使用者身分（access_token 拿到了），但因為命中雙向鎖、不能完成登入。將驗證結果暫存進 session 並帶 `verified_at` timestamp，blocked 頁的「強制終止」流程只要驗證該 timestamp 還沒過期，就可以直接 POST force-revoke → 解鎖並 `Auth::login` — **無需使用者再走一次 OAuth round-trip**。

`access_token` 也順手保留，若強制解鎖後需要再用就直接拿（avoid double OAuth）。

## 六、安全閘清單

實作層至少要把以下 14 條落地：

| # | 閘 | 違規行為 |
|---|---|---|
| 1 | 啟動者必須是 `super_admin`（透過 `permission:impersonate.access` 中介層 + `Gate::before` 自動通過） | 403 |
| 2 | 不可模擬 `super_admin` 角色持有者（保護「最高權限」） | 403 |
| 3 | 不可模擬自己 | 422 |
| 4 | 不可巢狀模擬：啟動前查 `impersonation_sessions WHERE impersonator_user_id=? AND ended_at IS NULL`，有 active row 就拒 | 422 |
| 5 | `reason_note` 必填、至少 5 字、varchar(255) 上限 | 422 |
| 6 | **唯讀守衛**：模擬期間所有非安全方法（POST / PUT / PATCH / DELETE）一律 403，僅 `POST /system/impersonate/stop` 白名單放行 | 403 |
| 7 | session 自動過期：超過 `config('impersonate.timeout_minutes')`（預設 60）無活動 → middleware 自動 stop（`end_reason='timeout'`） | — |
| 8 | admin 主動登出時 → 自動 stop（`end_reason='admin_logout'`） | — |
| 9 | 被模擬者帳號被停權 → 下個請求 force stop（`end_reason='target_disabled'`） | — |
| 10 | **雙向鎖：admin 端**：模擬中 admin 從別處 OAuth 登入 → callback 攔截、導 blocked admin 變體 | 重導 |
| 11 | **雙向鎖：target 端**：模擬中 target 從別處 OAuth 登入 → callback 攔截、導 blocked target 變體 | 重導 |
| 12 | **強制清雙方 sessions**：啟動 impersonate 時刪除 `sessions` 表內 admin 與 target 的所有 row（排除當前 session） | — |
| 13 | **target 端不可自行解鎖**：target blocked 頁無「強制終止」按鈕 | — |
| 14 | **target 端不顯示 reason_note**：blocked 頁與員工歷史頁皆不顯示 admin 啟動時的 `reason_note`（隱私） | — |

`#1` 與 `#2-#4` 應在 service 層 belt-and-suspenders 再防一層（permission middleware 把第一道、service 把第二道）。

## 七、唯讀守衛實作

掛 `TrackImpersonation` middleware 到所有後台路由（與 `auth` / `logRequest` 同層）：

```php
Route::middleware(['auth', 'setCurrentCompany', 'logRequest', 'trackImpersonate'])
    ->group(function () {
        // 後台所有路由
    });
```

middleware 邏輯：

```php
public function handle(Request $request, Closure $next): Response
{
    if (!$this->service->isActive()) {
        return $next($request);
    }

    // #9：target 帳號被停權 → 立刻 stop
    $currentUser = $request->user();
    if ($currentUser instanceof User && $currentUser->is_active === false) {
        $this->service->stop('target_disabled');
        return redirect('/')->with('flash_error', '被模擬者帳號已停權，模擬已自動結束');
    }

    // #7：timeout 自動 stop
    $startedAt = (int) Session::get('impersonate.started_at', 0);
    $timeoutMin = (int) config('impersonate.timeout_minutes', 60);
    if ($startedAt > 0 && (now()->timestamp - $startedAt) > $timeoutMin * 60) {
        $this->service->stop('timeout');
        return redirect('/')->with('flash_error', '模擬 session 超過閒置上限，已自動結束');
    }

    // #6：唯讀守衛（白名單放行 stop）
    if (!in_array($request->method(), ['GET', 'HEAD', 'OPTIONS'], true)) {
        if (!$request->routeIs('*.system.impersonate.stop')) {
            abort(403, '模擬模式為唯讀，禁止寫入操作');
        }
    }

    return $next($request);
}
```

**關鍵設計**：白名單用 `routeIs('*.system.impersonate.stop')` 比對路由名稱，不靠 path 比對 — 路徑前綴可能因 locale prefix（`/zh-hant/...`）而變動。

## 八、Timeout 兩層保護

| 層 | 觸發點 | 行為 |
|---|---|---|
| Lazy 清理（主） | admin / target 在 middleware 或 callback 任何一次 request | 偵測超時 → 立刻 stop |
| 排程兜底 | `impersonate:cleanup-expired` 每 5 分鐘跑 | 掃 active 但 `started_at < now - timeout_minutes` 的 row 標 ended（`end_reason=timeout`） |

只有 lazy 清理會「無人嘗試操作時記錄一直卡 `ended_at NULL`」— 例如 admin 啟動後直接關瀏覽器、target 也沒嘗試登入。排程兜底解這個 corner case。

排程設定在 `routes/console.php`：

```php
Schedule::command('impersonate:cleanup-expired')->everyFiveMinutes();
```

正式環境只要 cron 既已定期跑 `schedule:run`，無需額外設定。

## 九、路由與權限

```php
// app/Portals/Ocadmin/routes/ocadmin.php

// blocked 頁與強制終止：portal 級（無 locale prefix、無 auth）
//   - GET /impersonate/blocked       ← OAuth callback 雙向鎖攔截導過來
//   - POST /impersonate/force-revoke ← admin blocked 頁的「強制終止」按鈕
Route::get('/impersonate/blocked', [ImpersonateController::class, 'blocked'])
    ->name('impersonate.blocked');
Route::post('/impersonate/force-revoke', [ImpersonateController::class, 'forceRevoke'])
    ->name('impersonate.force-revoke');

// 員工自己的歷史頁：auth-protected
Route::middleware(['auth', 'setCurrentCompany', 'logRequest', 'trackImpersonate'])
    ->group(function () {
        Route::get('/impersonate/my-history', [ImpersonateController::class, 'myHistory'])
            ->name('impersonate.my-history');
    });

// 系統管理頁：受權限保護
Route::prefix('system')->name('system.')->middleware(['auth', '...'])
    ->group(function () {
        Route::prefix('impersonate')->name('impersonate.')->group(function () {
            Route::middleware('permission:impersonate.access')->group(function () {
                Route::get('/',                            [ImpersonateController::class, 'index'])->name('index');
                Route::post('/start',                      [ImpersonateController::class, 'start'])->name('start');
                Route::get('/history',                     [ImpersonateController::class, 'history'])->name('history');
                Route::get('/sessions/{uuid}',             [ImpersonateController::class, 'show'])->name('show');
                Route::post('/sessions/{uuid}/force-revoke-other', [ImpersonateController::class, 'forceRevokeOther'])
                    ->name('force-revoke-other');
            });
            // stop 不受 permission:impersonate.access 把關（模擬中的 target 視角不該有此權限）
            Route::post('/stop', [ImpersonateController::class, 'stop'])->name('stop');
        });
    });
```

**新增 permission**：`impersonate.access`（在衍生 branch 視 portal 命名空間決定前綴，例 `hrm.system.impersonate.access`）

**角色指派**：

- `super_admin`：靠 `Gate::before` 自動通過，無須顯式指派
- 其他角色：一律不指派 — 效果上即「只有 `super_admin` 能用本機制」

## 十、緊急解鎖管道

避免 admin 在 A 電腦啟動模擬後，B 電腦想處理急事卻被自己鎖死：

| 解鎖者 | 管道 | 結束原因 |
|---|---|---|
| admin 本人 | blocked 頁的「強制終止模擬」按鈕（靠 callback 暫存的 `impersonate.blocked_attempt` 驗證身份 → POST force-revoke） | `force_revoke` |
| 其他 super_admin | 模擬歷史頁可看到所有 active session，按「強制終止他人模擬」 | `revoked_by_other` |
| target 員工 | **無解鎖管道**（設計如此） | — |

target 員工的處置邏輯：若 admin 行為有疑慮，員工應走 HR 申訴管道，由其他 super_admin 介入。這是因應「員工沒有否決 audit」的設計權衡。

force-revoke 流程的安全要點：

```php
public function forceRevoke(Request $request)
{
    $blockedAttempt = Session::get('impersonate.blocked_attempt');
    if (!$blockedAttempt || $blockedAttempt['role'] !== 'impersonator') abort(403);

    // 時效檢查：blocked_attempt 不可無限期有效
    if (now()->timestamp - $blockedAttempt['verified_at'] > 600) abort(419, '驗證已過期，請重新登入');

    $session = $this->service->findBySessionUuid($blockedAttempt['session_uuid']);
    $admin   = User::find($blockedAttempt['user_id']);
    if (!$session || !$admin) abort(404);

    $this->service->forceRevoke($session, $admin);
    Session::forget('impersonate.blocked_attempt');
    Auth::login($admin);

    return redirect()->intended('/');
}
```

## 十一、環境差異與法遵

| 環境 | 啟用 | 備註 |
|---|---|---|
| local | ✅ | 開發者驗證用 |
| staging | ✅ | QA 重現問題用 |
| production | ✅ | 唯讀模式，風險主要在「敏感資料被檢視」，每次啟動都留 session + 動作軌跡 |

**法遵備註**：因採唯讀設計，無「以他人身分送出操作」的責任歸屬問題；剩餘風險為「敏感資料的檢視紀錄」。在 production 啟用前建議與 HR / 法務確認員工內規是否已揭露「管理者基於除錯需要可檢視員工資料」條款。

---

## 十二、不涵蓋

- **以他人身分寫入 / 代操**：唯讀設計刻意排除
- **修改被模擬者密碼 / OAuth 綁定**：本系統不存密碼，無此需求
- **API token 模擬**：本機制只覆蓋 web session
- **與 `dev login` 整合**：用途不同，兩者各自獨立
