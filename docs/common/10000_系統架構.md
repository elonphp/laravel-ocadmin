# 系統架構

## 核心觀點：這是一個 Laravel 專案

本系統的基礎是 **Laravel**。所有的路由、認證、授權、資料庫、佇列、快取 — 全部由 Laravel 掌控。

在 Laravel 之上，採用 **Portal 多入口架構**，讓同一個 Laravel 專案同時服務不同對象（後台管理員、員工、門市人員、前台訪客），每個入口有獨立的技術棧、角色與 URL 前綴。

```
┌──────────────────────────────────────────────────────────────┐
│                         Laravel 13                           │
│              路由 / 認證 / 授權 / ORM / 佇列 / 快取            │
│                                                              │
│   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│   │   Ocadmin    │  │     Hrm      │  │  POS Portal  │      │
│   │   Portal     │  │  （範例）     │  │  （範例）     │      │
│   │              │  │              │  │              │      │
│   │ Blade+jQuery │  │  衍生專案      │  │  衍生專案     │      │
│   │ Bootstrap 5  │  │  自行選型      │  │  自行選型     │      │
│   └──────────────┘  └──────────────┘  └──────────────┘      │
│                                                              │
│   ┌─────────────────────────────────────────────────────┐   │
│   │           共用：Models / Migrations / Services       │   │
│   └─────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

Portal 是本系統最重要的設計決策，詳見 [10001_Portal概述.md](10001_Portal概述.md)。圖底部「共用：Models / Migrations / Services」的完整資源對照（含 Helpers / lang / Views 等是否跨 Portal 共用）見 [10001 §5.2 Portal 間的共用資源](10001_Portal概述.md#52-portal-間的共用資源)。

## 技術棧（全系統）

按「技術層」分。各 Portal 各自前端選型的差異化對照見 [10001 §5.1 各 Portal 技術選型](10001_Portal概述.md#51-各-portal-技術選型)。

| 層 | 技術 | 說明 |
|----|------|------|
| **基礎框架** | Laravel 13 | 路由、認證、授權、ORM、佇列 |
| **語言** | PHP 8.5 | 後端語言 |
| **資料庫** | MySQL / MariaDB | 資料持久化 |
| **Ocadmin Portal**（本範本實作） | Blade + jQuery + Bootstrap 5 | 後台管理介面 |

本範本（ocadmin）的目的是示範 Ocadmin 後台，只實作 Ocadmin Portal。架構圖中其他 Portal（Hrm / POS / Web 等）是 Portal 多入口架構**可承載的應用入口類型範例**（Hrm Portal 內可含 mss / ess / team 等子模組），由衍生專案視需求自行採用或增減，與本範本無關。其他 Portal 的技術選型 / 前後端分離方案等研究筆記放在 [`docs/research/`](../research/)。

## 專案目錄結構

```
app/
├── Portals/                        ← 各應用入口（核心設計）
│   └── Ocadmin/                    ← 後台管理 Portal（本範本唯一實作）
│       ├── Core/                   ← 共用基礎（基底 Controller、Provider）
│       ├── Modules/                ← 功能模組（HRM、Catalog 等）
│       └── routes/
│
├── Models/                         ← Eloquent 模型（跨 Portal 共用）
├── Services/                       ← 跨 Portal 共用 Service
├── Helpers/                        ← 輔助工具（OrmHelper、DateHelper 等）
└── Http/
    └── Middleware/                 ← 共用 Middleware

config/
├── portals.php                     ← Portal 設定（url_slug、role_prefix、dir）
└── ...

database/
├── migrations/                     ← 所有資料表遷移
└── seeders/

lang/                               ← 多語系語言檔
├── zh_Hant/
└── en/
```

## 為什麼不採用前後端完全分離

本系統的使用情境：

| 問題 | 答案 | 結論 |
|------|------|------|
| 需要 Mobile App 共用 API？ | 否 | 不需要獨立 API |
| 需要第三方系統串接？ | 否 | 不需要 API-first |
| 有獨立前端團隊？ | 否 | 不需要分離開發 |
| 面向大眾、需要 SEO？ | 官網需要，後台不需要 | 官網 Portal 另行評估 |

**採用 Portal 架構的優勢：** 各 Portal 各自選擇最適合的技術棧（Blade 或前後端分離皆可），而不是強制整個系統使用同一種前端方式。

需要 API 時（如行動 App 或第三方串接），可直接在對應 Portal 加入 API 路由，與現有 Portal 並存，不需重構整個系統。

## 業務模組範例

| 業務功能 | Portal | Controller | 路由前綴 |
|----------|--------|-----------|---------|
| 系統設定 | Ocadmin | `Ocadmin\System\SettingController` | `/admin/system/setting` |
| 員工人資管理 | Ocadmin | `Ocadmin\Hrm\EmployeeController` | `/admin/hrm/employees` |

Portal 內 `Core/` vs `Modules/` 結構、中介層判定、Controller 命名與 Model 位置規則見 [10001 §六 Portal 內資料夾階層](10001_Portal概述.md#六portal-內資料夾階層)。完整的 Ocadmin 模組規範詳見 [00003_Ocadmin程式規範.md](00003_Ocadmin程式規範.md)。
